## 状態の語彙

保証の強い順に並べてある。**「実装」と「記述」を混ぜないことがこの表の要点。**

| 状態 | 意味 | 必要な根拠 |
|---|---|---|
| **実装** | コードがあり、自動テストが挙動を証明している | `T:` |
| **実機** | CSS に実体があり、実ブラウザで実測した | `C:` と `B:` |
| **記述** | CSS に実体があり、**約束した値まで機械検証している**。ただし描画結果は実機でしか確かめられない | `C:` と `T:` |
| **未検証** | コードはあるが自動テストが無い。**素直な穴** | `S:` |
| **委譲** | ネイティブ側が担う。こちらが何も書かないのが正解 | `N:` |
| **合成** | 利用側が組み立てる。レシピを示す | `D:` |
| **ロードマップ** | 未実装。どの版で入れるかを示す | `R:` |

根拠の記法。検証器が実在を確かめる。

| 記法 | 検証内容 |
|---|---|
| `T:テスト名` | `tests/` に同名の `it()` がある |
| `S:パス` | ファイルが存在する |
| `C:文字列` | `src/styles.css` に含まれる |
| `D:パス` | ファイルが存在する |
| `B:見出し` | `VERIFICATION.md` に含まれる |
| `R:項目名` | `ROADMAP.md` に含まれる |

`prefers-reduced-transparency`（S-04）や `forced-colors`（S-06）は、jsdom ではメディアクエリごと
無視されるため、テストは書けても意味がない。実ブラウザのエミュレーションで検査する必要がある。

全部を「実装」に引き上げた。ただし **jsdom で証明したのは配線であって、実機の体験ではない。**
何をどこまで証明したかを正直に書き分ける。

| ID | jsdom で証明したこと | jsdom では証明できていないこと |
|---|---|---|
| T-06 | 長押し・右クリック・テキストへのクリックのいずれでも展開しないこと。`user-select` / `touch-action` を奪っていないこと | 実機の iOS / Android で、実際にコンテキストメニューが期待どおり出ること |
| B-11 | `autoplay` / `loop` / `muted` を付けず、`controls` と `preload="metadata"` を付けること。ギャラリー経由でも同じ | 実機で音が鳴らないこと（jsdom は `HTMLMediaElement` の再生を実装していない） |
| F-10 | `Cmd/Ctrl + Enter` が primary だけを起動し、ゲート中・処理中・修飾キーなしを正しく素通しすること | OS ごとのキーリピートと IME 変換中の挙動 |
| G-06 | **リフローで本文の寸法が変わったとき、読了判定が再評価されること。** 一度満たした読了が縮小で取り消されないこと | 実際に 400% 拡大したときのリフロー結果そのもの。寸法はテストが差し替えている |
| M-04 | `visualViewport` の縮みが `--g-keyboard-inset` に正しく出ること。`offsetTop` を引くこと。負にならないこと。閉じたら購読も変数も残さないこと | 実機の仮想キーボードが `visualViewport` をどう動かすか |
| M-07 | `closeOnBack` のときだけ履歴に印を積み、`popstate` で `back-button` として閉じ、閉じた後は拾わないこと | 実機の戻るジェスチャと、Next.js App Router の履歴操作との相互作用 |

**G-06 と M-04 は「合成された証明」である。** 寸法とビューポートをテストが差し替えているので、
証明しているのは *入力が変わったときに正しく反応する配線* であって、*実機での入力値* ではない。
実機側は [`ROADMAP.md`](../ROADMAP.md) の v0.4.0（Playwright + axe）に残す。

**必須（M）でありながら「記述」の項目**は、`npm run check:trace` が毎回一覧で出力する。
これがこのライブラリの現在の弱点であり、隠さずに出す。
